'@labre/affine': minor
---

A host may lock a source's properties and its new rows. New optional `sourcePolicy(databaseId, sourceId)` on the data-source picker, answering a signal of `{ propertiesLocked, rowsLocked }` (new type `DataSourcePickerSourcePolicy`, `@labre/affine/shared/services`) for every view of a host database (a block with an `externalSourceId`) that reads that source; a flip of the signal reaches the open views. Properties locked: no "+" column, no "Insert left / right", no rename, type change, duplicate or delete in a property's menu (its name shown read-only with "The properties of this source are locked"), no "New property" in the properties list or the record detail; hiding, ordering, widths, filters, sorts, groups, colour rules and cell values stay. Rows locked: "New" drawn disabled with "New pages cannot be added to this source" and without its menu, no "+" in group headers, table footers, boards, galleries and lists, no "Insert before / after" on a card, no keyboard row; existing rows stay editable and deletable. Both are also refused by the view layer (`SingleView.rowAdd` answers `''`, `propertyAdd` `undefined`, and a property's `nameSet`, `typeSet`, `duplicate` and `delete` write nothing), read from the new `SingleView.propertiesLocked$` / `rowsLocked$`, `Property.nameCanSet` and `DataSource.propertiesLocked$` / `rowsLocked$`. Two new keys: `com.labre.data-view.source.properties-locked`, `com.labre.data-view.source.rows-locked`. A host without `sourcePolicy` sees no change.
