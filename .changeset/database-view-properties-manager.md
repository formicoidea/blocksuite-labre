A view's « Properties » list manages the properties, as in Notion, wherever it is drawn: the view options' "Properties" and the database's side panel (`affine-database-properties-panel`), for every view type, kanban, gallery and list included. A click on a row (not its eye, not its drag bar) opens the property's menu, the very one the table's column header opens: rename, type, hide in view, duplicate, delete. A last row « New property » adds one at the end of the source through the type picker, then opens its menu for the rename. Rename, type, duplicate, delete and add write the data source, so every view sees them; hiding and reordering stay per view. Read-only, the rows open nothing and « New property » is not drawn; the title keeps the header's rules (no type change, no hide, no delete). The menu is now one core builder, `propertyMenuItems(property, slots?)` / `popPropertyMenu(target, property, slots?)` in `data-view/src/core/common/property-menu.ts`, which the table header opens with its own entries (number format, filter, sort, insert, move) as slots; the header's menu is unchanged. `data-view-properties-setting` takes an optional `wording` (English without it), as do `popPropertiesSetting`, `typeConfig` and the menu builder; the table header resolves it from the editor. The menu's "Hide In View", "Duplicate" and "Delete", the "Property type" title and the popover's "Properties" now cross the translation seam ("Duplicate" and "Delete" reuse `com.labre.toolbar.{duplicate,delete}`; "Properties" reuses `com.labre.database.properties-panel.title`, now declared by `@labre/data-view` as `DATA_VIEW_PROPERTIES`, `PROPERTIES_PANEL_TITLE` being that wording). Nothing stored changes. New keys (FR in the host): `com.labre.data-view.properties.new`, `com.labre.data-view.property.{type,hide-in-view}`.
