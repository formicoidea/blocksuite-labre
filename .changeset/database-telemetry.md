Database telemetry (ADR 0035 §12, B17), documented in the telemetry README's new "Databases" section with the boundary between the library's `Database*` events and the host's own `base.*`. New events, ids and closed vocabularies only, never a row id, a value, a title or a name: `DatabaseViewAdded { viewType, source: 'existing' | 'new' }` (the views bar's "+" and "Create …"), `DatabaseViewTypeChanged { fromViewType, toViewType }` (the Layout switch), `DatabaseGroupChanged { groupBy, propertyType? }` (every grouping menu, through `GroupTrait`), `DatabaseRowOpened { mode, newTab, rowKind }` (every preset's row open, gallery and list included, from the database block's `openDetailPanel` once B9's row-open request is built: the host's mode, `side` for the library's own peek or detail) and `DatabaseValuesLoadFailed { retryable }` (once per failure of a hosted source). Filters and sorts keep their historical `CreateDatabaseFilter` and `DatabaseSort*` series. `AddDatabaseView` is no longer emitted (replaced by `DatabaseViewAdded`); it and the never-emitted `CreateDatabaseView`, `ChangeDatabaseLayout` and `CreateDatabaseGroup` stay in `TelemetryEventMap`, deprecated. A host that forwards `track(event, props)` needs nothing; one that types an exhaustive `Record<keyof TelemetryEventMap, …>` adds the five keys. New in `@labre/data-view`: `DataViewEventTraceKey` (the tracer a database block gives its source), `traceViewEvent`. New in `@labre/affine-block-database`: `rowOpenedParams`.
