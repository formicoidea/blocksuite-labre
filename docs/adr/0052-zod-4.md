# ADR 0052 — zod 4, the same documents

- Status: **accepted** (2026-11-17)
- Deciders: the product owner chose the real migration over the `zod/v3`
  compatibility subpath (issue #667); the red-zone change awaits a
  maintainer's approval on its PR.
- **Red zones**: `packages/framework/store` (`model/block/zod.ts`,
  `transformer/type.ts`) and `packages/affine/model` (the enum schemas of
  `consts/`, the style schemas of the note, frame and edgeless text). Nothing
  persisted changes: no Yjs key, no schema, no stored value, no default is
  written that was not written before, and every document that opened under
  zod 3 opens and round-trips the same.
- Related: GHSA-mrhx-c7xc-m3w5 (zod 3 has no fixed release), ADR 0008 (the
  command registry and its agent manifest), ADR 0050 and 0051 (the read-only
  viewer under a strict policy).

## Context

zod reaches every host through `dependencies` of `@labre/store`, `@labre/std`,
`@labre/affine-model` and most feature packages, so through
`@formicoidea/labre-core`. The 2026-W47 hygiene pass (#667) found
GHSA-mrhx-c7xc-m3w5 in zod 3.25, fixed only in 4.6.6. zod 4 also ships a
`zod/v3` subpath that keeps the zod 3 API; the product owner rejected it: it
carries the same code, so it would carry the advisory too, and it postpones
the move rather than making it.

zod is not only a type library here. It decides, at run time, what a document
holds and what a host reads:

1. `BlockSchema` checks every block schema a store registers;
   `BlockSnapshotSchema`, `SliceSnapshotSchema` and `DocSnapshotSchema` check
   every snapshot, and the edgeless clipboard keeps the PARSED snapshot.
2. Every inline delta's attributes are normalised through the intersection of
   the inline specs' schemas before they are written to a `Y.Text`.
3. A new element takes its style from `NodePropsSchema` (its `.default`
   values), `makeDeepOptional` and the host's `EditorSetting`.
4. A database reads a stored cell back through its column's `rawValue`
   schema, and falls back to the default when the schema refuses it.
5. The agent manifest describes a command's parameters by reading its zod
   schema (`describeCommandParams`).

zod 4 changes, without a type error, several things those paths depend on:

| zod 3                                                                                                                | zod 4                                                                                      | Where it would have shown                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.default(v)` parses `v` through the schema                                                                          | `.default(v)` returns a shallow copy of `v`, unparsed; `.prefault(v)` is the old behaviour | every element created from one style default would share its nested objects (`labelStyle`)                                                                                   |
| `_def.typeName` names the schema kind                                                                                | gone; `_zod.def.type` (`'object'`, `'optional'`…)                                          | `describeCommandParams` returned nothing for every command: the manifest silently empty                                                                                      |
| `.refine()` wraps in a `ZodEffects`                                                                                  | the refined schema keeps its type, with a `custom` check                                   | a refined parameter, undescribable before, would have been described without its refinement                                                                                  |
| `nativeEnum` and `enum` are two kinds                                                                                | one `enum`; `z.enum(SomeEnum)` accepts an enum object                                      | a string native enum parameter would have entered the manifest                                                                                                               |
| `z.record(value)`                                                                                                    | the key schema is required: `z.record(z.string(), value)`                                  | a compile error (snapshot `props`, link-preview storage)                                                                                                                     |
| `z.function().args(…).returns(…)`                                                                                    | `z.function({ input: […], output })`                                                       | a compile error (block schema, paragraph and linked-doc options)                                                                                                             |
| `.merge(other)`                                                                                                      | deprecated; `.extend(other.shape)`                                                         | nothing; moved anyway                                                                                                                                                        |
| no `eval`                                                                                                            | the first object schema built probes `new Function`, then compiles parsers with it         | a `script-src` report on a host page whose policy has no `'unsafe-eval'` (the viewer's)                                                                                      |
| a key whose schema takes `undefined` (`z.undefined()`, `z.any()`, `z.custom()`, `X.or(z.undefined())`) may be absent | only an `.optional()` (or defaulted, or caught) key may be absent                          | the code block's and the LaTeX editor's inline managers refused EVERY delta (their `z.undefined()` unit key), dropping its marks; `makeDeepOptional` refused a partial style |
| `number()` takes `Infinity` and `-Infinity`                                                                          | `number()` refuses them                                                                    | a stored number, date or progress cell holding `Infinity` (a number column parses "1e999" so) read as empty; a stored filter argument stopped applying                       |

The last two were not on the list the migration started from: the guard
specs found them, on the first run under zod 4.

## Decision

1. **Every manifest declares `zod ^4.6.6` and imports from `'zod'`.** No
   `zod/v3`, no `zod/mini`. The lockfile resolves a single zod 4; zod 3 no
   longer appears in it.
2. **Behaviour is held, not re-decided.** Two guard specs recorded every
   outcome above under zod 3.25 before the code moved, and the snapshots are
   byte-identical under zod 4: `framework/store/src/__tests__/zod-format-guard.unit.spec.ts`
   (snapshot schemas, `BlockSchema`, base text attributes) and
   `affine/all/src/__tests__/zod-format-guard.unit.spec.ts` (every block
   schema's default props, every surface element type's stored defaults, the
   model style schemas, `NodePropsSchema` / `makeDeepOptional` /
   `pickStylePropsForKey` / `EditorSetting`, the default inline manager's
   attribute schema, every database column's value schemas, and the agent
   manifest's parameter contract). A diff there is a format or contract
   change, which takes an ADR, not a snapshot update. Three cases were added
   after the first zod 4 run showed what the first list missed (the code
   block's and LaTeX editor's inline managers, ±Infinity and `NaN` in every
   column); their expectations are zod 3's, checked against zod 3.25 with
   the same schemas outside the library. The baseline was touched twice, and
   only in what it records, never in what it holds: a frame's
   `presentationIndex` is drawn at random (now redacted), and a failing path
   is recorded once (zod 3 reported `.int().refine()` twice, zod 4 once).
3. **Object style defaults are `.prefault()`**, zod 4's spelling of zod 3's
   `.default()`: `NoteZodSchema`, `FrameZodSchema`, `EdgelessTextZodSchema`
   and the defaults of `NodePropsSchema`. Primitive defaults
   (`z.boolean().default(false)`) stay `.default()`: a primitive is never
   shared. `makeDeepOptional` unwraps both, and makes a union `.optional()`
   where it appended `.or(z.undefined())`.
4. **A key that could be absent says so.** The two inline unit keys are
   `z.undefined().optional()`. An audit of every `z.object` key whose schema
   takes `undefined` found no other one a document or a host reads (the
   database's `UserInfoSchema` keys are a data schema nothing parses).
5. **A stored number keeps its infinities.** `storedNumber()`
   (`affine/database/engine`, `core/logical/stored-number.ts`) is
   `number() | ±Infinity`, zod 3's `number()`: the value schemas of the
   number, date, progress and created-time columns and the number and date
   value types the filters check use it. Every other `number()` reads a
   gesture, JSON (which has no infinity) or a host setting, where refusing
   `Infinity` changes nothing anyone could have stored.
6. **`describeCommandParams` reads `_zod.def`**, and keeps zod 3's answers: a
   refinement anywhere (a `custom` check) withdraws the contract, as a
   `ZodEffects` did; an `enum` is described as `string` only when it is a
   `z.enum([...])` of strings (every key equal to its value), so a native enum
   stays undescribed, as a `ZodNativeEnum` was; `.prefault` reads as
   `.default`. Describing native string enums is a separate manifest
   decision, left with a `ponytail:` line.
7. **The library never sets zod's global configuration.** zod 4 reads
   `jitless` when a schema is built and the library builds its schemas while
   its modules evaluate, so `mountCanvasViewer` is too late to set it (the
   probe has already run when `@labre/store` was imported), and only an
   import-time side effect would be early enough. That flag is global to every
   zod on the page, including the host's own, and every package is
   `"sideEffects": false`: a host's page configuration is the host's. A host
   that serves the viewer (or the editor) under a policy without
   `'unsafe-eval'` calls `config({ jitless: true })` from `zod` in a module
   its entry imports before any library module, which the Labre app's web
   entry already does for its own forms
   (`docs/integrate/09-static-html.md`). zod falls back to interpreted
   parsing either way: without the line, the viewer still paints and only the
   report remains. `canvas-viewer-csp.spec.ts` loads that module first and
   asserts nothing is refused, and a second frame without it asserts the
   `eval` report is raised, so the requirement cannot rot into folklore.
8. **This is a major release.** zod types are part of the public surface:
   `CommandDescriptor.params` is a `z.ZodType`, `BlockSnapshotSchema`,
   `SliceSnapshotSchema` and `DocSnapshotSchema` are exported schemas,
   `InlineSpecs.schema`, `AttributeService.setAttributeSchema` and the view
   extensions' option schemas take zod schemas. A host that passes the library
   a zod 3 schema stops compiling.

## Consequences

- Stored documents: unchanged, by construction and by the two guards. Every
  document written by a zod 3 client opens under zod 4 and a zod 4 client
  writes nothing a zod 3 client cannot read.
- Hosts: use zod `^4.6.6` for every schema handed to the library (command
  `params`, inline specs, option schemas), dedupe so one zod 4 instance
  serves both, and set `jitless` on any page under a no-`eval` policy. The
  changeset and `docs/integrate/07-upgrade.md` say so.
- Performance: an untouched default page keeps zod 4's compiled object
  parsers; a `jitless` page parses interpreted, which zod measures as slower
  but which none of the paths above is sensitive to (one parse per gesture,
  per snapshot, per delta).
- Debt: the `ponytail:` line on native enums in `describeCommandParams`
  (`framework/std/src/extension/command-registry.ts`) is the only one.
