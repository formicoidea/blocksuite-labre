zod 4 (ADR 0052, GHSA-mrhx-c7xc-m3w5, #667). Every package now depends on `zod ^4.6.6` instead of zod 3, and the zod types in the public API are zod 4's: `CommandDescriptor.params`, the exported `BlockSnapshotSchema`, `SliceSnapshotSchema` and `DocSnapshotSchema`, `InlineSpecs.schema` (now `z.ZodType<Partial<Record<string, unknown>>>`), `AttributeService.setAttributeSchema`, `BlockSchemaType` and the view extensions' option schemas. What a host does: build every schema it hands the library with zod `^4.6.6` (`z.function({ input, output })` instead of `.args().returns()`, `z.record(z.string(), value)` instead of `z.record(value)`), and dedupe to one zod 4 instance. On a page whose Content-Security-Policy has no `'unsafe-eval'` (the canvas viewer on a public page, or the editor), call `config({ jitless: true })` from `zod` in a module the entry imports before any library module: zod 4 probes `new Function` when it builds its first object schema, which the library does while its modules evaluate, and the library never sets that global flag itself; without it everything still works and the policy reports one `eval`. Stored documents are untouched: block and element defaults, snapshot parsing, inline attributes, database values read back, the creation style and the agent manifest's parameter contracts are byte-identical to zod 3 (two guard specs pin them), and nothing new is written. Two zod 4 behaviours are neutralised to keep that true: an object key that may be absent is now declared `.optional()` (the code block's and LaTeX editor's inline managers would otherwise refuse every delta), and stored number, date, progress and created-time cells keep reading `Infinity` through the new `storedNumber()` of `@labre/affine-database-engine` (zod 4's `number()` refuses it).
