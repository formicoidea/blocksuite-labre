A stored database view whose mode has no preset here (a `timeline` from an import, a mode written by a newer client) renders as a table instead of throwing `Unknown view type` and blanking the whole database (ADR 0035 §6). `viewMetaGet` never throws: the database answers the table preset over the source's properties. Such a view reads the table's default settings, never rewrites its stored data (`SingleView.dataUpdate` is a no-op on it), keeps editable cells, and its tab says "Shown as a table" (`com.labre.data-view.view.shown-as-table`); its menu offers "Duplicate as table" (`com.labre.data-view.view.duplicate-as-table`) instead of rename, Edit View and Duplicate. New on `SingleView`: `shownAsFallback$`; new in `@labre/data-view`: `duplicateAsShownPreset(manager, viewId)` and `./translations` (`DATA_VIEW_WORDINGS`). Calendar becomes render-only: a stored calendar view still renders and edits as a calendar and can still be switched to a table or a board, but no path creates one any more (the slash "Calendar View" entry is gone, `databaseBlockViews`, the list the views bar and Layout read, no longer holds calendar, and `databaseBlockViewConverts` drops the conversions into calendar). New exports: `databaseBlockRenderableViews`, `databaseBlockFallbackView`, `databaseBlockViewMetaGet(mode)`; `databaseBlockViewMap` has no prototype, so a mode named `constructor` falls back too. The view menu's Duplicate and Delete now read the toolbar's keys (`com.labre.toolbar.duplicate`, `com.labre.toolbar.delete`).
