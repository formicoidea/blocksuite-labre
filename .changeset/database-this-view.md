The full page of a database lists its view settings for a host's menu, and a view can be imported from another database (ADR 0035, amendment of 2026-10-14; labre PRD REQ-DB-2, DB-4, DB-10). **"This view":** `<affine-database-page>` registers six `'view-menu'` commands (`database.view.layout`, `.group`, `.open-in`, `.properties`, `.save-template`, `.import`), so `getViewActions(std, 'page')` lists them and `runViewAction` runs them, on the full page only; a setting opens the very menu of the view settings entry (`openSetting(key)` of the view's options button, `popViewSetting` in `@labre/data-view`), listed where the view offers it and never on a read-only page. New keys `com.labre.database.view-menu.{layout,group,save-template,import}` ("Layout", "Group", "Save as template", "Import a view…"); "Open pages in" and "Properties" reuse `com.labre.data-view.open-in` and `com.labre.database.properties-panel.title`. **Import and templates, through the picker:** `DataSourcePickerService` gains two optional verbs, `importView(request)` (the host picks a view and maps its properties, then calls `request.add({ view, properties, mapping })`, which copies it as a new view on the current view's source, one undo step) and `saveViewTemplate(template)` (the current view without its filters, sorts and manual orders). "+ view" adds "Import a view from another database" (`com.labre.database.add-view.import`) when the picker imports. `remapView`, `defaultMapping` and `viewTemplateData` (pure, `@labre/core-database`) preview the copy for the host's dialog. `DatabaseViewAdded.source` gains `import`. No stored field changes.
