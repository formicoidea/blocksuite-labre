# Host seams

**Every place the library asks the host for something, and what disappears
when the host provides nothing.**

The library never talks to a backend, an analytics service or a search
index. It exposes a service identifier; the host registers an implementation
as an extension in the editor specs. Most seams are optional: the code reads
them with `std.getOptional(...)` and degrades. The table below says how.

All identifiers are exported from `@labre/affine/shared/services` unless
noted. Register with `di.override(Provider, () => impl)` or the ready-made
`XExtension(impl)` helper.

**Hosted database sources.** `HostedDataSourceBase(hostModel, resolveSource)` (ADR 0035 §7, B1) keeps the views in `hostModel.props.views`; each view names the source it reads by its stored `sourceId` (absent on every view stored before 0.49). `resolveSource(sourceId)` returns `{ schema, rows }`: the `affine:database` block whose `props.columns` is that source's schema, and a signal of its ordered row ids; `null` when there is no such source. The data layer (`rows$`, `schema$`, and the getters your subclass implements over `schema$`) answers for the current view's source; `sourceMissing$` says when it has none. Nothing is written while resolving. A source whose rows are documents overrides `rowsAreDocuments` (`true`), answers each title from its own store with `titleOf(rowId)` and returns `hostedTitleColumnConfig` from `propertyMetaGet('title')` (ADR 0035 §9f, B15): the title is a plain string drawn and edited by the plain-text cell, a committed title reaches your `cellValueChange` as a string, and no row's document is loaded to draw it.

**Full-page database and "+ view" (`@labre/core-database`, ADR 0035 B11, B13).** No seam of their own. A database page is the inline table moved to a page: mount `<affine-database-page .store=${store} .extensions=${pageExtensions} .hostBlockId=${id}>` (exported as `DatabasePageHost` from `./view`, defined by `DatabaseEditorViewExtension`) with the database document's store and the page extensions you would give its page editor (its `DatabaseDataSourceProvider` answering a `HostedDataSourceBase` for the views' block); `element.std` is the editor it builds. Give it your `<doc-title>` as `.heading`, since the page title is the database's name: the page draws it above the views in its own viewport, the page's only scroller (a table view scrolls with it both ways, its column header sticky), so do not wrap the page in a viewport of your own. Set the title's `bodyBlockId` to the same id: Enter and ArrowDown then leave the title for the database (the first cell of a table or kanban view) and never add a paragraph to the note; without it the title keeps the page behaviour of 0.48 and writes into a note this page never draws. It draws the views' block alone, without its title row and without the page root's chrome or handlers; the schema blocks and the note are never drawn, never selectable (the guard owns the store's selection: mount no other editor on that store meanwhile) and a file drop never reaches them; nothing inserts into the note and nothing is written; without a block of that id it says "This database has no views to show." (`com.labre.database.page.host-missing`). The view bar is core's: as many tabs as the width allows, the rest under "N more" (`com.labre.data-view.views-bar.more`, `{{count}}`), the current view always a tab, 44px targets on a phone. With `DatabaseEditorToolingViewExtension` registered, its "+" on a source that resolves sources offers "On an existing source" (each source the views read, by its schema block's title, plus, with your `DataSourcePickerExtension`, the sources of the block's database, its `externalSourceId`, that no view reads yet) and, when your picker has `createSource`, "With a new source" (it calls `createSource(externalSourceId)`, then adds a table on the new source); a new view stores the `sourceId` of the source it was added on. Without the bundle, or on an inline database, "+" lists the creatable presets.

**Cell hydration.** When values arrive after rows (ADR 0035 §9e, B2), answer `cellStatus(rowId, propertyId)` with `pending` until the value is the real one (`error` if it failed), and `valuesState$` with `{ status: 'loading' | 'ready' | 'error', since: Date.now() }` for the whole source; offer `retryValues()` if you can try again. A pending cell draws a spinner (`LoadingIcon`) centred in it, a failed one stays empty; neither mounts its editor nor accepts a write (a paste, a fill or a kanban drop on it does nothing). Group counts and column statistics show "…" until `ready`; after 3 s of `loading` a banner says values are still loading (`com.labre.database.values.loading`), and on `error` a banner says they could not be loaded (`com.labre.database.values.error`) with Retry (`com.labre.resource.status.retry`) when `retryValues` exists. The library writes nothing in any state.

**Fonts.** `CommunityCanvasTextFonts` is a sane default but points at `fonts.cdnfonts.com`: a host that promises no third-party request self-serves the files and passes the same list with its own `url`s. A family with no face in the registered list is not offered by the text font-family picker; a text already stored in it keeps it, paints the `sans-serif` fallback and shows the family name greyed as unavailable, and nothing is rewritten. Neither default list carries Satoshi since #396 (its licence forbids offering it as a selectable font in a SaaS); Plus Jakarta Sans (SIL OFL 1.1) replaces it.

**Title band.** `sheet$(docId)` returns a signal synchronously (`loading`, `ready`, `missing`, `error`, as for pivot properties); `ready` holds the page's **visible** properties in the order to draw them, `{ id, namespace, name, type, data, value, readonly }`, where `type` and `data` are a data-view property type and its config and `value` the JSON a data-view cell of that type holds. You resolve visibility; a visible property with no value comes back with `value: null` and draws an empty chip that can still be clicked. Each value is drawn and edited by the cell the inline table mounts for its type, with the table's look (ADR 0035 §11, amended 2026-10-13): the checkbox toggles, `select` and `multi-select` open the table's tag menu (on your options only, unless the property may change them: see below), `date` opens the table's date picker, `number`, `progress` and the text types (`text`, `rich-text`, `title`, `email`, `phone`) the table's inputs; `link` and `url` are drawn by the database block's link cell when its view extension is registered, by the text cell otherwise; `created-time` and `modified-time` are drawn read-only by the date cell. A number reads as in a table cell: unformatted unless `FeatureFlagService` turns `enable_database_number_formatting` on. Any other type keeps a plain-text reading that opens your properties panel, or nothing. A value the cell commits calls `set(docId, propertyId, value)` (`null` for an emptied one, nothing for an unchanged one): the chip shows pending until the promise settles, and the new value must come back through `sheet$`, since the band never applies it. A rejection is yours to report and roll back. The band is drawn by `<doc-title>` under the title and by the page note's head on the canvas, inside the note, so it follows the zoom; on the canvas it is interactive while the note is being edited, like the rest of the note. `notShown$(docId)`, optional, is the list of child pages this document holds but does not display (labre ADR-0045 §7); the band draws it in both views as a "Not shown on this page" row. A page's title opens it through `RefNodeSlotsProvider.docLinkClicked`; its "Show here" (`com.labre.title-band.show-here`, writable documents only) inserts an `affine:embed-linked-doc` card of it, at the end of the last note in the page view and at the centre of the visible canvas on the canvas, as one undo step. The library writes only that card: you compute the list, and you drop the page from it once your reading of the document finds the card. Do not draw a row of your own under the title: the band already does. `children$(docId)`, optional (0.60), is the ids of the child pages of document `docId` in your page tree (labre ADR-0045, amended 2026-10-27): a linked-doc card or a synced-doc embed of one of them in that document is the child's own card, and draws the plain page (or canvas) icon instead of the linked-page icon whose arrow marks a reference; an inline `@` reference always keeps the arrow. It is read inside the card's icon computation, so a move redraws the card. The library computes no parent and no child.

**Title band options.** A `select` or `multi-select` chip creates and renames options only when your service has `setData(docId, propertyId, data)` and the property comes with `dataWritable: true`, on a chip that is not `readonly`. Then the tag menu offers "Create" and a rename field per option (no delete, no colour, no reorder: those stay in your properties panel). Each change calls `setData` with the whole config, `{ ...data, options }`, options in `{ id, value, color }` with a created option first; a creation is followed by a `set` that selects it, so apply the two in order. The band never applies `data`: the new options come back through `sheet$`. A rename sends one call per keystroke, as the table does; coalesce if you need to. A rejection is logged. Do not mark `dataWritable` a select whose option ids are its labels (the Labre app's `tags`): a rename would change its values.

**Thread marks.** `marks$` is a signal of `{ targetType: 'block' | 'element', targetId, count, unread }` for the document the editor shows (ADR 0038): `block` for a block in either view, canvas notes, frames, images and embeds included; `element` for a canvas element no block backs (a shape, a connector, a group, a framework board). The editor draws a mark (the comment icon and `count`, accent when `unread`) beside each marked block in the page view and on the top-right corner of each marked model on the canvas; an id it cannot find, a `count` of `0` or less and what this viewer has hidden get none, two marks on one target are summed. Every toolbar that speaks for one target offers "Discuss" (`com.labre.thread.discuss`). A click on either calls `openThread({ docId, targetType, targetId, excerpt })`: `docId` is the store's id, `excerpt` the block's text (a note's paragraphs) or the element's label as the selection pane reads it, else its kind, whitespace collapsed, at most 280 characters. Store it beside your anchor; the editor keeps no copy, writes nothing to the document and emits no telemetry for it (`openThread` is your event). `threadExcerpt(std, { targetType, targetId })` (`@labre/affine/host-panels`) gives the same excerpt for a discussion you start from your own UI.

**Thread marks on a run of text** (ADR 0038, amendment of 2026-10-15). "Discuss" on a text selection still targets the block (the first one, when the selection covers several) and adds `range: { start, end }` to the request; `excerpt` is then the selected text of that block. Both strings are Yjs relative positions on the block's text, encoded by the editor: store them as they are, never parse them, and hand them back as `range` on a `block` mark. The editor highlights that run in the page view (the `block/comment/*` colours), resolves it on every render so it follows every edit, local or remote, and calls `openThread` with the same `range` when a reader clicks it with nothing selected; the block's own mark is drawn as before. A run whose text was deleted, or a string that is not one of its positions, is simply not highlighted; the block's mark stays. Nothing is written to the document: no prop, no attribute in the text (AFFiNE's inline comment, which writes `comment-<id>` into the text, is not used). A host that ignores `range` keeps the block-level behaviour unchanged. On the canvas a run keeps only its block's mark.

**Database rows and sources.** `DatabaseOpenRowExtension` is the one path every view takes to open a row (`DataViewRootUILogic.openDetailPanel`); a host that routes rows to its own pages reads `mode` and `newTab` and does the navigation. `DataSourcePickerExtension.list()` returns a signal of `{ id, title, sources: [{ id, title }] }`, where `id` is the `externalSourceId` the inserted block will carry (opaque to the library); the picker reads it as it draws, so a list filled late shows up. `importView(request)` receives the database the copy lands in (`databaseId`), the current view's `sourceId`, that source's `properties` and the `layouts` it adds: let the reader choose a view (any database it may read, or a template you kept), map each of its properties to one of `properties` or ignore it, then call `request.add({ view, properties, mapping })`; the library copies it as a new view on that source (one undo step), removing the filters and sorts on ignored properties and every conditional colour rule that reads one (ADR 0036), and returns its id or `null` (the page turned read-only, a layout not offered). `remapView` (`@labre/core-database`) gives the same copy and its counts beforehand (`dropped.filters`, `.sorts`, `.group`, `.properties`, and since 0.50 `.colorRules`), for your dialog to say what is removed. `saveViewTemplate(template)` receives the current view without its filters, sorts and manual orders, with its conditional colours and its source's properties; keep it where you keep templates and offer it back through `importView`. The full page of a database registers its "This view" entries as `'view-menu'` commands (`database.view.layout`, `.group`, `.open-in`, `.properties`, `.color-rules`, `.save-template`, `.import`): list them with `getViewActions(std, 'page')` on the page's `std` and run them with `runViewAction`; a setting opens the view settings' own menu on the view's options button. A picked source is inserted as an `affine:database` block with that `externalSourceId`, the database title and one view with that `sourceId`, as one undo step; a board on a source with nothing to group by lands as a table. `popDataSourcePicker` (`@labre/core-database/view`, with `databaseId` for one database's sources) is the picker a "+ view" opens. `DatabaseNewRowMenuExtension.open` receives the chevron as `anchor` to hang your menu from, the `affine:database` block and the view; the library draws nothing of the menu and adds no row for it: a template you apply is your own write. A hosted source that offers a text column lists `hostedTextColumnConfig` (`@labre/affine/blocks/database`, type `text`, a plain string value) in `getPropertyMetas` and returns it from `propertyMetaGet('text')`: data-view's own plain-text preset is hidden from the menus, because the inline database's Text is `rich-text`.

**Saved frames.** `FrameTemplateProvider` changes no stored format. "Save as template" on the toolbar of ONE selected frame calls `save({ docId, frameId, title, snapshot })`: `snapshot` is a `DocSnapshot` of the frame, its descendants (groups opened, nested frames included) and the notes it holds, serialized by the surface transformer, so every stored key of every element crosses unchanged except `layer` (dropped: the copy lands in the inserting viewer's active layer, ADR 0031 §6) and a connector end outside the frame (turned into a free position, as a paste does). Images and attachments are referenced by their blob id, never copied. The library shows the outcome (`com.labre.frame.toast.template-saved`, or `com.labre.frame.toast.template-save-failed` on a rejection) through `NotificationProvider`, or its own toast: do not notify yourself. With `showTemplates` (since 0.54), the success notification carries one action, « View » (`com.labre.frame.toast.template-view`), that calls it: open the place where the viewer finds the saved template. The fallback toast has no button. A read-only viewer may save too, since nothing is written to the document; refuse in `save` if you must. `list()` returns `{ id, title, snapshot, preview? }` and is called only when the Templates panel shows the "Saved frames" tab (`com.labre.template.panel.category.saved-frames`, last tab, identity `SAVED_FRAMES_CATEGORY`) or searches across tabs, never at mount; a tile is inserted by the canvas template job like any template (fresh ids, the frame's children remapped, active layer). `frameDeleted({ docId, frameId })` is called for a frame THIS viewer deleted on a writable document, never for a deletion another peer made, and for every frame (ignore ids you do not know); `frameRestored` is called when this viewer brings back, in the same session, a frame it had deleted (undo). Whatever `frameDeleted` does must be undone by `frameRestored`: move to the trash, never destroy. Make both idempotent: two editors on one document report the same gesture twice. `frameInserted({ docId, templateId })` is called once a tile of the "Saved frames" tab is on the canvas (after the template job resolved, never for a failed insertion), with the document it landed in and your `id` for the template: link what the copy references (its images) to that document, or a guest of that page will not see them. Absent, nothing is called. A host category of its own goes through `TemplateCategoryExtension(category)` (`@labre/affine/gfx/template`), per editor; the module-level `EdgelessTemplatePanel.templates.extend(...)` is gone.

**Exports of a view.** No seam: the editor never asks you for an export, you list and run them. `getViewExports(std, mode?)` (`@labre/affine/host-panels`) returns the view actions of section `'export'` for the view you show: `page.export.markdown` and `page.export.html` in both views, and on the canvas `canvas.export.png`, `.pdf` (with an `ExportManager`), `.drawio`, `.svg` (whole canvas) and one `canvas.export.<framework>.<format>` per `*:export` capability a framework registered (so its flag decides), listed while the board holds that framework's elements. `runViewAction(std, id)` resolves with `{ file }` (a `Blob` and a sanitised name) and downloads nothing; the same commands run from the palette download. Ids, labels, `labelParams` and icon keys: [08-host-panels.md](08-host-panels.md#exports-of-a-view).

**Pasting in a page.** No seam of its own: what a paste offers follows from seams already in this table. Plain text that is ONE http(s) URL and nothing else (`lonePastedUrl`, `@labre/affine-inline-link`) still pastes as a plain link, then the link's own toolbar opens on it, as on a hover, so its view switcher offers "Card view" and "Embed view" beside "Inline view" (labre REQ-IM-1). Nothing is converted unless the reader picks one; the next key or a press outside the toolbar closes it and the link stays. "Card view" is offered when the bookmark view (or the card of an embed provider matching the URL) is registered, "Embed view" when an embed provider or an `EmbedIframeConfigExtension` matches the URL and its view is registered; the embed is the sandboxed iframe of that registry. The proposal asks nothing of the network: only a view the reader picks may, through the link-preview service, whose default endpoint is in the table. A URL your `ParseDocUrlExtension` recognises becomes a reference to that document, not a link, and opens nothing. A sentence holding a URL, a `mailto:` and a refused scheme paste as text. Pasted text that holds a GFM table becomes an inline table (`affine:table`), never a database, whether it is pasted or imported as Markdown: every cell keeps its text, escapes resolved, extra cells kept as columns, an image as a link named by its alt text (REQ-IM-2). On the canvas a paste outside a note is unchanged (a URL lands as a card); a paste inside a note being edited takes the page path above.

**Asset dialog.** `AssetPickerProvider` changes no stored format. `pick({ kind, mode, multiple?, docId })` is called by the slash menu's Image (`kind: 'image'`, `multiple: true`), Attachment and PDF (`kind: 'file'`, `multiple: false`), the same entries of the mobile keyboard toolbar, the canvas's image and file buttons (`gfx/note` menu), all with `mode: 'insert'`, and by "Replace" on the page image toolbar and "Replace with image" in the canvas image toolbar's "Replace" menu (`canvas.image.replaceWithImage`, ADR 0044 amendment of 2026-10-27) (`mode: 'replace'`, `multiple: false`, first ref used). `docId` is the document the result lands in: attach the asset to that page there, or a guest of the page will not see it. Resolve with `AssetRef[]` (`{ sourceId, name, type, size, width?, height? }`) for blobs your blob source already serves under `sourceId`; upload a new file into your library inside the dialog and resolve with its ref, the editor never gets a `File` through the seam. `null` or `[]` means cancelled: nothing is written. A rejection is logged and nothing is written: show your own error first. The blocks reference `sourceId` (an image keeps `size`, `width`, `height`; a card keeps `name`, `type`, `size`); the library never calls `BlobSource.set` for them and reads the blob once (`BlobSource.get`) only to measure an image whose ref has no `width` or `height`. An image ref whose `type` is not `image/*` is ignored. "Replace" writes the new `sourceId` and `size` in one undo step and keeps the caption: in a page the block keeps its `width` and its `height` follows the new ratio (an image still at its natural size stays so); on the canvas the frame keeps its top-left corner and width, its height follows the ratio. Picking the image already shown writes nothing. Nothing is written on a read-only document; "Replace" is not offered there. Without a host the same entries open the system file chooser instead. "Replace with image" on a plain shape's toolbar (ADR 0044) calls `pick({ kind: 'image', mode: 'replace', multiple: false })` too, first ref used, and puts an image block cut to the shape's box in its place (new id; box, rotation, depth, layer, connectors, group and frame kept; one undo step). The functions are exported for a host's own entry points: `addSiblingImageBlocksFromAssets`, `addImagesFromAssets`, `replaceImage` (`@labre/affine/blocks/image`), `addSiblingAttachmentBlocksFromAssets`, `addAttachmentsFromAssets` (`@labre/affine/blocks/attachment`).

**Theme.** The theme is a host seam with two halves.

- _Which scheme is in force._ `ThemeService` (`packages/affine/shared/src/services/theme-service.ts`) asks the `ThemeExtensionIdentifier` registration for two signals: `getAppTheme()` for the page editor and `getEdgelessTheme(docId)` for the canvas. Each is optional; a missing one is replaced by an observer on `document.documentElement.dataset.theme`.
- _What the colours are._ The library reads `@toeverything/theme` two ways: as CSS variables by their `--affine-*` names (in styles, through `cssVar` / `cssVarV2`), and as JS tables of values where a `var(…)` cannot go. Canvas painters resolve a variable through `ThemeService.getCssVariableColor`, which looks it up in `combinedLightCssVariables` / `combinedDarkCssVariables` (the chrome accent on the canvas, `getChromeAccentColor`, goes that way); the toolbars (`packages/affine/components/src/toolbar/styles.ts`) bake values from the same tables into their own selectors; the model builds the canvas palette from `lightThemeV2` / `darkThemeV2`.

- _Dark mode, host side._ Set `data-theme="dark"` on the page's `<html>` (or answer `getAppTheme()` / `getEdgelessTheme(docId)` with `dark` through `ThemeExtension`) and the editor follows: the chrome through its `--affine-*` tokens, the canvas by repainting. The notations keep their hues; their paper and inks resolve through a dark table at paint time, never written into the page (ADR 0039). Nothing else to register: the dark palettes are the library's own, registered by each framework. The SVG export always paints light; the PNG export paints the scheme in force. The experimental DOM renderer (`enable_dom_renderer`) does not follow the dark table yet.

So **a CSS-only override of an `--affine-*` variable does not re-skin the editor**: it repaints the DOM that reads the variable, but not the canvas painters, the toolbars or the canvas palette, which read the package's JS values. To substitute the theme, override the package itself in your package manager with a copy of your own, e.g. `pnpm.overrides["@toeverything/theme"] = "link:./packages/theme"` (the Labre app does this). The substitute keeps every `--affine-*` variable name and exports every name the library imports, listed in [01-install.md § Styles](01-install.md#styles) and frozen by `theme-imports.unit.spec.ts` (`packages/affine/all`). Mind the canvas palette: a colour picked from it is stored on the element as a value, so changing `edgeless/palette/*` or `edgeless/note/*` changes what new elements write into documents (DESIGN.md, The Untouched Data Rule).

**Pages dragged in from the host.** `PageDropProvider` changes no stored format: a drop writes one ordinary `affine:embed-linked-doc` card, the block "Show here" and a pasted page link make. On every native dragover the editor calls `verdict({ types, docId })`, with the `dataTransfer.types` the browser exposes then (never the data: know which page you drag from your own state) and the open document's id. `'ignore'` leaves the drag to the editor as before; `'refuse'` draws no drop line and lets the browser show its no-drop cursor (a read-only document refuses whatever you answer); `'accept'` draws the drop line. On the drop of an accepted drag (no files) the editor calls `drop({ dataTransfer, docId })` once, synchronously: do what the drop means to you (move the page under `docId`) and return `{ pageId, undo?, redo? }`, or `null` to place nothing. The card goes on the drop line in a note (page view, or a note on the canvas), else centred on the drop point on the canvas (CRUD `addBlock`, active layer), else at the end of the last note in the page view; it is one undo step, and `undo` / `redo` are called when that step is undone or redone, after the card left or came back. A step whose card another peer already removed is skipped by the history, and your hooks with it. If the card cannot be placed, `undo` is called at once. A drop into an editor nested in another (a synced page's content) is placed once, by the innermost editor.

## How to read this table when something is missing

If a button "never existed", check the seam before filing a bug. The Labre
application documents each of its registrations in
`apps/web/src/modules/editor/extensions.ts` with the reason; copy that habit.

## How to add a seam (library side)

1. Define the identifier and the extension helper next to the service.
2. Read it with `std.getOptional(...)` and decide the degraded behaviour
   explicitly (hide the button, log once, fall back).
3. Add a row to this table.
4. Give it a test that mounts without the provider.
